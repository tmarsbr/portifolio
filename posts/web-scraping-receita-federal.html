Pipeline de Web Scraping: Extração de Dados Públicos da Receita Federal

#python #apache-spark #aws #web-scraping #aws-lambda #amazon-emr

A Receita Federal disponibiliza mensalmente os dados abertos de CNPJ do Brasil — são dezenas de gigabytes de arquivos CSV compactados, com informações de todas as empresas ativas e inativas do país. O desafio: coletar, tratar e carregar esses dados de forma automatizada e escalável.

O Problema

Muitas empresas precisam cruzar dados do CNPJ para validação cadastral, análise de mercado ou compliance. Fazer isso manualmente é inviável — são mais de 50 milhões de registros distribuídos em múltiplos arquivos com schemas inconsistentes.

Arquitetura da Solução

Desenhei um pipeline end-to-end com as seguintes camadas:

  1. 01DescobertaIdentificação automática dos arquivos mais recentes no portal público.
  2. 02ExtraçãoDownload controlado, verificação de integridade e registro da execução.
  3. 03Camada RAWPreservação dos arquivos originais no S3, particionados por referência.
  4. 04ProcessamentoPadronização e transformação distribuída com Apache Spark.
  5. 05ConsumoDados em Parquet, catalogados e disponíveis para consultas no Athena.
  • Extração: Script Python com requests e BeautifulSoup que navega no portal da Receita, identifica os links de download mais recentes e baixa os arquivos ZIP automaticamente.
  • Armazenamento raw: Os arquivos brutos são enviados para o AWS S3 na camada RAW, com particionamento por data de extração.
  • Processamento: Jobs Apache Spark rodando no Amazon EMR descompactam, padronizam schemas e aplicam transformações de limpeza (remoção de duplicatas, normalização de campos, cast de tipos).
  • Orquestração: AWS Lambda dispara o pipeline mensalmente via EventBridge, e monitora o status de cada etapa.
  • Consulta: Os dados processados ficam em Parquet no S3 e são consultáveis via Amazon Athena, sem necessidade de provisionar banco de dados.

Decisões Técnicas

Escolhi Spark no EMR em vez de Pandas por uma razão simples: volume. Com 50M+ de registros, Pandas estoura a memória de uma máquina comum. O Spark distribui o processamento em cluster e permite escalar horizontalmente conforme o volume cresce.

O particionamento em Parquet por UF e data de referência permite que queries no Athena leiam apenas os blocos necessários — reduzindo custo e tempo de resposta em até 90%.

Resultados

  • Pipeline executa mensalmente sem intervenção manual
  • Tempo de processamento: ~45 minutos para o dataset completo
  • Dados consultáveis em segundos via Athena
  • Custo mensal de infraestrutura: < US$ 15
Tolerância apertada e processo confiável geram qualidade — em aço e em dados.

Tecnologias Utilizadas

  • Python (requests, BeautifulSoup)
  • Apache Spark
  • AWS S3, Lambda, EMR, Athena
  • EventBridge (agendamento)
  • Parquet (formato de armazenamento)
